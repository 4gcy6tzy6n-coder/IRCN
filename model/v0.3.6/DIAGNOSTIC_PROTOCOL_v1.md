# IRCN v0.3.6 WP2 Single-Instance Diagnostic Protocol v1

**Status:** draft pending independent pre-run review. This protocol is normative together with `DIAGNOSTIC_CONTRACT_v1.yaml`; any conflict is resolved in favor of the stricter rule, and must be fixed before execution. No diagnostic variant may run until both files receive independent `ACCEPT`.

## Hash timing

Do not calculate hashes while diagnostic variants are running. Preserve raw arrays, event logs, resolved configurations, counters, failures, and timestamps as emitted. First terminate all variants and finish the raw analysis, failure records, and result table. Then perform the post-run archival phase: calculate semantic hashes, hash the complete output tree, and verify the manifests. Write the final status only after this archival phase. Pre-run review-receipt, frozen-source, environment, and generated-input checks remain setup gates and must complete before the experiment clock starts; they are not part of variant execution. During variant execution, repeat identity is checked through direct equality of the persisted trajectories, event streams, counters, and normalized configurations; archival hashes are supplementary post-run evidence.

## Question and limits

This nonconfirmatory diagnostic investigates only the frozen WP2 validation instance `chain / N=128 / dense_burst / seed=128012`. It asks whether the observed candidate trajectory discrepancy is reproducible and whether delivery mode, scalar versus batched local integration, or either of two separately predeclared tolerance tightenings materially changes it. It does not repair or re-open WP2, validate the influence predictor, change any gate, or authorize WP3–WP6. WP2 remains `INCONCLUSIVE` and WP3–WP6 remain `BLOCKED`, regardless of outcome.

## Frozen identity and reproduction gate

Before candidate execution, verify all parent contract, raw label, instance, source snapshot, and input-trace hashes listed in the YAML. Recompute the parent source manifest; require exactly 96 matches and zero mismatches. Verify the instance key and input trace hash before loading any candidate scheduler. A mismatch means record `BLOCKED`, preserve evidence, and stop without substituting or reconstructing data.

The baseline is `broadcast_batch`, batch size 2, local `rtol=1e-9`, `atol=1e-11`, segment tolerance `1e-7`, maximum segment interval `0.02 s`, exact exogenous input, and unchanged parent task settings. Run this exact baseline twice. To reproduce the parent WP2 value, use its exact formula over all 201×128 entries: `NRMSE = sqrt(mean((candidate-oracle)^2)) / max(sqrt(mean(oracle^2)), 1e-12)`. A zero RMS denominator uses the specified floor (it is not a separate failure). Define max absolute error over the same entries. Each repeat must match NRMSE `0.00864007689194927` and max error `0.006075382462433044` within absolute tolerance `1e-12`, and match counters exactly: 54,752 events; 13,834 deliveries; 40,818 queue pushes; 506,341 RHS evaluations; 25,728 output materializations. The two repeats' full trajectories, event streams, counters, and normalized computational configurations must be bitwise identical; compare these values directly during the run, without hashing. The post-run archive separately calculates semantic and configuration hashes; each run's full resolved configuration includes variant/repeat/run identity and is expected to differ. Any failure closes the reproduction gate: report `BLOCKED`, keep WP2 `INCONCLUSIVE`, and run no other variants.

## Variant order and controls

After the reproduction gate passes, run each remaining variant exactly once, in YAML order: `edge_delivery_batch2`, `broadcast_delivery_scalar`, `edge_delivery_scalar`, `tighter_local_tolerance`, `tighter_segment_tolerance`. The two baseline repetitions are the only repeated runs. No variants, parameter values, reruns, or threshold searches may be added after execution begins. Every output directory must have a unique run ID and creation must refuse overwriting an existing directory. Persist the complete resolved configuration for every variant. All variants use the same frozen graph, weights, input trace, duration, sample times, zero initial state, and deterministic event tie-break order. The local tolerance variant changes only local `rtol=1e-11`, `atol=1e-13`. The segment variant changes only segment tolerance to `1e-8`; it retains local tolerances, delivery, batch size, max interval, and all other settings.

## Independent oracle check

Use the frozen segmented DOP853 oracle (`rtol=1e-13`, `atol=1e-15`) with every declared input discontinuity as a segment boundary. Independently implement the full-state right-hand side without calling `System.rhs` or `solve_ivp`: `W[target,source]`, `f(h,x)=(-h+tanh(W@h+U@x+b))/tau`, initial state all zeros. Integrate classical RK4 with maximum steps 0.001 s and 0.0005 s. Define integration boundaries as the sorted union of start/end times, all input breakpoints, and all frozen 0.01 s sample times. No RK4 step may cross a boundary; shorten its final step to land exactly on each boundary. Record only states at RK4 step endpoints; do not interpolate. At a boundary shared by sample time and input breakpoint, finish the preceding interval using the left-limit input, record the continuous state once, and start the next interval from that same state with right-continuous input. Restart the step grid at every input breakpoint and sample time. In the final RK4 stage of a step ending at an input breakpoint, evaluate the input at its left limit; the first stage of the next step uses right-continuous input at that breakpoint.

Save DOP853, RK4-0.001, and RK4-0.0005 trajectories and all pairwise NRMSE and max-absolute errors. For any two trajectories A and B, `NRMSE(A,B)=sqrt(mean((A-B)^2))/max(sqrt(mean(B^2)),1e-12)`; report both orientations. RK4 refinement is corroborated only if max absolute error ≤ `1e-9` and both directional NRMSE values are ≤ `1e-9`. Each RK4 trajectory agrees with DOP853 only if max absolute error ≤ `1e-8` and both directional NRMSE values are ≤ `1e-8`. When comparing candidate closeness to an oracle, use `NRMSE(candidate, reference)` with each reference as the second argument. Interpret all cases explicitly:

1. If RK4 refinements fail either pair limit, the independent check is nonconverged; do not use RK4 to assign root cause.
2. If RK4 refinements converge but either refinement fails a DOP853 limit, report oracle disagreement and unresolved reference validity.
3. If refinements converge and both agree with DOP853, report independent corroboration for this instance only.
4. If the candidate is closer to RK4 than DOP853, report that fact with both metrics; do not replace the frozen oracle or reclassify the WP2 result.

## Frozen comparisons and interpretation

For each variant, save full trajectory, candidate-versus-DOP853 NRMSE and max absolute error, candidate-versus-both-RK4 errors, per-sample NRMSE, time/node of maximum error, all deterministic event/RHS counters, input/instance hashes, and failure/timeout information. Per-sample NRMSE applies the same formula over nodes at each sample, with reference RMS denominator and `1e-12` floor. When max error is tied, select earliest sample time and then smallest node index. Save arrays as float64 `.npy` with recorded shape. JSONL is UTF-8, one JSON object per line, with recursively sorted keys, one object per line, exactly one final LF, and deterministic event ordering.

For each preregistered contrast, compute direct pairwise trajectory NRMSE and max absolute difference between the two candidate trajectories; pairwise NRMSE is reported in both orientations using the same formula above. Separately report signed differences in each candidate's oracle-relative NRMSE and max absolute error for direction only. Use the full variant IDs in the YAML; the four contrasts are baseline repeat 1 vs edge batch2, broadcast scalar vs edge scalar, baseline repeat 1 vs broadcast scalar, and edge batch2 vs edge scalar. For the error interaction, calculate `(edge_batch2 - broadcast_batch2) - (edge_scalar - broadcast_scalar)` separately for oracle-relative NRMSE and max absolute error. Delivery equivalence requires direct pairwise trajectory max absolute difference and both orientations of pairwise NRMSE ≤ `1e-8`; scalar/batch equivalence uses the same limits. Any exceedance is a localized discrepancy, not an efficacy claim. The local tolerance sensitivity criterion is at least a 10-fold reduction in candidate-versus-DOP853 NRMSE versus baseline; report max-absolute error too. The segment tolerance variant is descriptive and uses the same two candidate-versus-DOP853 metrics.

All variants must be attempted once after the baseline gate, even when one variant fails, unless the process is interrupted by a system-level inability to continue. Record each exception or timeout with variant ID, stack trace, partial outputs, and status; do not silently retry or omit it. Failures do not authorize replacement runs.
