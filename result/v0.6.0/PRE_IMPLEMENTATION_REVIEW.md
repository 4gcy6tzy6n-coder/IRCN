# v0.6.0 pre-implementation review

Review mode: independent architecture review followed by owner scope correction. A first draft was **rejected** by the independent reviewer before code or test-label generation. This file records the rejection and the resolutions made before implementation.

## Initial findings

| ID | Severity | Finding | Resolution |
|---|---|---|---|
| B1 | Blocker | Task generator prose deferred crucial ranges and sample mapping to future code. | Fully specify graph, pulse distributions, draw order, trajectory count, seed mapping, and split unit in the contract and YAML. Golden hashes must be produced and frozen before training/test labels. |
| B2 | Blocker | v0.5 event ordering and elapsed-time semantics do not match the proposed v0.6 readout/training semantics. | Scope v0.6 to a synchronous differentiable reference and counterfactual label/predictor bridge. Explicitly prohibit learned event-runtime deployment and parity claims in this stage; v0.5 remains unchanged. Runtime integration becomes a later versioned milestone. |
| B3 | Blocker | Local state, aggregate, current input, and degree still cannot distinguish nodes at different distances from the readout. | Add capped directed distance and readout reachability; add a full-feature collision adversary. If complete features collide with materially different Delta, stop before training. |
| B4 | Blocker | Endogenous message opportunities cannot also be identical across policies with exact budget matching. | Remove scheduler/budget comparison from scope. Every node/tick is an offline label opportunity in the reference; no runtime scheduling or efficiency inference. |
| M1 | Major | Intervention timestamp, scored horizon, simultaneous peer actions, liveness override, and sequence-tail handling were ambiguous. | Define snapshot at the start of tick t, all other nodes update identically in both branches, score exactly t..t+3, and only label t=0..11. Liveness is out of scope. |
| M2 | Major | “All path nodes have nonzero Delta” was not generally true for finite horizons, and feedback-memory was not in frozen task scope. | Remove generic nonzero-path assertion and unregistered memory task. Add a specific hand-computed sparse-path fixture; isolated nodes must be zero. |
| M3 | Major | dt=1 training did not support elapsed-time scheduler updates with dt>1. | No event scheduler deployment in v0.6; cell is trained/evaluated at dt=1 only. dt>1 behavior remains explicitly unvalidated for later runtime integration. |
| M4 | Major | Learnability threshold and NRMSE aggregation/zero-variance handling were incomplete. | Define per-trajectory NRMSE denominator, preserve undefined zero-variance rows, compare against constant training-mean baseline, and separate software readiness from cell learnability and estimator performance. |
| M5 | Major | Training checkpoint selection, preprocessing leakage, label imbalance, and opportunity subsampling were underspecified. | Freeze epoch-level validation, min_delta/patience/checkpoint rules, train-only feature/label statistics, all opportunities, seed-balanced path/isolated weighting, and all-label retention. |
| M6 | Major | Single-node scores were described like a joint budget optimum. | Rename to single-intervention label oracle; joint-set optimum is explicitly not estimated. |
| M7 | Major | All-UPDATE runtime parity would not validate HOLD/deadline/event behavior. | Remove runtime parity from this bridge stage; it will be an explicit later runtime-integration gate, with mixed HOLD/UPDATE and event-phase tests. |
| M8 | Major | No verified version-specific PyTorch lock existed. | Pin PyTorch 2.11.0 and its resolved direct/transitive environment for the current Python 3.12.13/macOS arm64 CPU-only machine; verify import, package consistency, and deterministic CPU operations before training. |
| M9 | Major | The draft stated 23 predictor features although the listed fields sum to 27. | Recomputed the dimension before implementation, corrected the contract/YAML to 27, and require a code-level feature-shape assertion. |

## Current scope status

`model/v0.6.0/MODEL_CONTRACT_v0.1.md` and `pre_registration_v1.yaml` freeze the synthetic task generator, seed-level splits, cell, predictor, counterfactual estimand, features, metrics, and failure rules. The YAML now contains canonical ndarray serialization and precomputed external-sentinel input/teacher hashes, plus the exact feature and hand-computed path-label fixtures. Initialization, optimizer, batch ordering, weighting, ranking ties, random baseline, bootstrap, and the descriptive held-out learnability descriptor are frozen. This remains a pre-implementation state until the second independent review accepts the revisions. The package consistency check passes in the current Python 3.12.13/macOS arm64 environment (`pip check` reports no broken requirements); training code and test labels have not been produced.

The second review identified a remaining golden-fixture mismatch in the collision adversary. An independent hand-coded recurrence check (before model code or label generation) found the node-5 expected Delta is `0.0832`, not `0.0512`; the YAML and contract were corrected, and the node-6 expectation `0.1025` and path-label fixture `0.016384` were verified. The first attempt at this check also had a checker mistake (subtracting squared outputs rather than squared errors against the teacher); that checker was corrected before fixing the fixture. The same review requested explicit metric applicability for ranking-only controls and an exact width-8 component mapping for the collision fixture; both were added. Input, teacher, and feature golden hashes pass. A clean virtual environment was created from the complete pinned lock; package check, YAML parse, and deterministic finite/nonzero CPU gradient smoke pass. Final independent contract re-review is pending; no train/test labels or model code have been generated.

The v0.3.5 WP2 result remains INCONCLUSIVE under its original contract and is not rewritten or imported as v0.6 evidence.
