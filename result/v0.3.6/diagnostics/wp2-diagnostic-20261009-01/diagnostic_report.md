# IRCN v0.3.6 WP2 单实例诊断报告

## 范围与状态

本报告只覆盖预注册的 validation / chain / N=128 / dense_burst / seed=128012 单实例诊断。状态为 `COMPLETED_DIAGNOSTIC`：两次冻结基线重现门通过，所有预定变体均完成。该状态不代表 oracle 独立核验通过，也不构成性能或模型能力证据。WP2 仍为 `INCONCLUSIVE`，WP3–WP6 仍为 `BLOCKED`；本结果不授权 E2/WP3，也不能改变父阶段结论。

## 观测事实

- 两次 `broadcast_batch` 基线均得到 NRMSE `0.00864007689194927`、最大绝对误差 `0.006075382462433044`，并逐项匹配预注册计数：54,752 events、13,834 deliveries、40,818 queue pushes、506,341 RHS evaluations、25,728 output materializations。
- 批量 edge-message 与批量 broadcast 的轨迹完全相同；标量 edge-message 与标量 broadcast 的轨迹完全相同。两个配对比较的直接轨迹差为 0。
- 标量两种传递方式均得到 NRMSE `1.4816112255684292e-09`、最大绝对误差 `7.340848345860351e-10`。其调度时间分别约为 23.27 s 和 23.24 s。批量基线约为 17.81 s，edge 批量约为 17.48 s。
- 收紧局部积分容差后，NRMSE 为 `0.016325109076998707`；收紧分段容差后为 `0.012131687421112397`。两者均未改善冻结基线的 oracle 相对误差。
- 独立 RK4 两个步长的 refinement 最大绝对差为 `8.381031168444575e-06`，双向 NRMSE 约 `2.719e-06`，未达到预注册 `1e-9`。它们与 DOP853 的差异也未达到 `1e-8`：细步长最大绝对差约 `8.381e-06`，NRMSE 约 `2.719e-06`。因此 independent check 标为 nonconverged，不能据此核验 DOP853 或裁决候选根因。
- 输出、失败记录、时间、预运行审查回执和哈希清单保存在本目录。归档修订记录为 `postrun_archive_revision.json`；它保留首次归档清单与状态文件哈希。实验执行时源码版本哈希留在 `run_metadata.json`，未被更改。

## 解释（非确认性）

本实例中，传递方式（broadcast 与 edge messages）没有改变轨迹；标量与批量本地积分却产生显著差异。标量配置显著接近 DOP853，但运行更慢。结合局部容差收紧未改善误差，现有结果提示批量本地积分路径是值得排查的实现敏感点，而传递模式不是本实例误差的主要解释。由于独立 RK4 核验未收敛，这只是对当前实现的诊断性解释，不能称为已确认根因。

这些计时只适用于本次冻结 CPU 环境与单实例设置。标量路径更接近参考轨迹并不代表 IRCN 有效率优势；本次没有开展一般任务、规模扩展或连接组增益验证。
